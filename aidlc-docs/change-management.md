# Change management

## Purpose

Protect the accepted inception baseline from accidental drift while still allowing deliberate changes.

## Process

1. Identify the needed change and why it is necessary.
2. Create a CHG file from `changes/CHG-template.md`.
3. Describe the impacted documents and units.
4. Record the decision and current status.
5. Link the CHG from affected unit work and pull requests.

## Minimum CHG content

- Summary
- Reason
- Impacted units
- Decision
- Status

## Rules

- Do not silently rewrite accepted requirements.
- Rejected or deferred changes should remain documented for traceability.
