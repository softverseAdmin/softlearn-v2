# Functional design: U0-7-security-and-compliance-design

## Purpose

Set the security and compliance baseline that later feature units must follow.

## User story

As a platform team, we need a clear security baseline so privacy-sensitive product areas are designed safely from the start.

## Functional requirements

- Document personal data protection expectations.
- Document consent and audit requirements.
- Document role-based access and secure authentication needs.
- Document meeting URL and future file-upload constraints.

## Inputs

- Requirements baseline
- Persona model
- Architecture direction

## Outputs

- Security and compliance document

## User flow

1. Identify protected data and actions.
2. Define guardrails.
3. Feed later units with reviewable constraints.

## Acceptance criteria

- Privacy, audit, and role-based access requirements are explicit.
- The baseline covers exam integrity and validated meeting links.

## Out of scope

Framework or provider-specific implementation detail.
