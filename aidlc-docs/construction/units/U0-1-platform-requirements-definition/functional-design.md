# Functional design: U0-1-platform-requirements-definition

## Purpose

Capture the platform's baseline functional scope before any stack decision or implementation begins.

## User story

As a project team, we need a stable requirement baseline so later units can design and build against the same product intent.

## Functional requirements

- Define student, company, and admin actors.
- Define core learning, exam, vacancy, matching, interview, and privacy capabilities.
- Record non-functional themes that shape later design.

## Inputs

- Product vision
- Initial problem statement
- AI-DLC operating rules

## Outputs

- Approved inception requirements document
- Traceable input for later inception units

## User flow

1. Gather baseline product goals.
2. Group requirements by actor.
3. Confirm cross-cutting constraints.

## Acceptance criteria

- Actors and major capabilities are listed clearly.
- Privacy-sensitive expectations are visible.

## Out of scope

Technology choice and detailed implementation behavior.
