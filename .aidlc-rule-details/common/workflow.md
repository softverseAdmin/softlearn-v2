# Workflow

## Purpose

Describe the end-to-end AI-DLC workflow used in this repository.

## Flow

1. **Inception**: define requirements, personas, feature breakdown, architecture direction, technology comparisons, and baseline constraints.
2. **Construction**: execute one unit at a time using the required unit documents and stage progression.
3. **Review**: run repository checks, automated review tools, targeted tests, and privacy/security review.
4. **Pull request**: submit a scoped PR for the unit or approved change request.
5. **Merge**: merge only after review gates pass and the change is understood.

## Principles

- No application-code generation before the stack decision is accepted.
- Small units and clear document history are preferred over broad changes.
- Requirement changes after baseline acceptance must go through CHG management.
